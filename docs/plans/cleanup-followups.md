# Native clone integration follow-up

Owner-requested extraction, 2026-11-06.

- [ ] Native guest API owner: implement the clone behavior below at the existing native message boundary. The retired Boa implementation registered only the old runtime's global `structuredClone`; it did not wire a worker mailbox or MessagePort caller. No independently reusable current helper was found. `JsObject` identity, `Context`, intrinsics, `TypedArrayKind`, `AlignedVec`, `JsArrayBuffer::detach`, DOM `NodeRef` checks and Boa errors bind that implementation to the removed runtime. The requirements here replace it; restoring it is not a prerequisite for this work.

  Current source boundary: `packages/blitz-script/src/native/web.rs` defines `PortState` with `Rc<RefCell<VecDeque<Value>>>` queues. `Web.MessagePort.postMessage` queues argument 0 directly, ignores transfer/options arguments, and `drain_message_port` places the same value in `MessageEvent.data` before queuing the callback. `onmessage`, `start` and `web_poll` drain the inbox; closed ports return without sending. `native/value.rs` clones `Rc<RefCell<Object>>` handles, so this path aliases sender objects rather than cloning them. `native/mod.rs` implements `IPC.postMessage` as a string-only host callback, not a structured-value transport. No Worker or `structuredClone` implementation was found in this crate's current source. `native/builtins.rs` stores ArrayBuffer bytes as indexed values; `make_typed` copies input bytes, resets byteOffset to zero and creates another buffer. It has no detach primitive that can substitute for Boa's. The DataCloneError code constant in `native/web.rs` is only an exception constant.

  Required behavior and acceptance cases, not claims of current support:

  - Graph and cycles: a clone is independent of the sender, but repeated references within it retain identity. Preserve self-cycles, mutual cycles, Map key/value and Set references, repeated Date/RegExp references, and shared backing-buffer identity across all views and explicit buffer references. Allocate receiving containers before resolving edges. Preserve array length and holes. Traverse deep user graphs without unbounded Rust recursion. For any future cross-thread payload, keep sender runtime handles out of the payload and reconstruct objects in the receiving realm; do not treat native Rc handle copies as transport serialization.
  - Values and properties: retain undefined, null, booleans, numbers (including NaN, infinities and negative zero), UTF-16 strings, and BigInt precision when that native type is supported. Clone own enumerable string/index properties into ordinary receiving objects/arrays, ignoring symbol keys and non-enumerable properties; do not copy prototypes or accessor descriptors. Read getters in property order with depth-first traversal and propagate their thrown exceptions. Preserve Map/Set insertion order, Date time including invalid dates, and RegExp source/flags with fresh lastIndex. Copy untransferred ArrayBuffer bytes independently. Preserve typed-array kind, element count, byte offset and DataView byte length, including valid empty views, using the same cloned backing buffer. The old patch covers Int8/Uint8/Uint8Clamped/Int16/Uint16/Int32/Uint32/BigInt64/BigUint64/Float32/Float64 views; do not silently reinterpret unsupported native types as plain objects.
  - Transfer input: support an iterable transfer sequence in the applicable API's options/overload. Missing structuredClone input, malformed options, non-iterable transfer lists, malformed iterator results and primitive transfer entries require TypeError as in the reviewed API contract. Propagate iterator/getter exceptions, and close the transfer iterator on abrupt entry processing. Reject duplicate entries, already detached buffers and unsupported transferable objects with DataCloneError. The historical transfer scope was ArrayBuffer only, not MessagePort or SharedArrayBuffer; do not infer port-transfer support from this patch.
  - Ownership and detachment: validate the full transfer list and finish graph serialization before detaching any sender buffer. Recheck all transfers after getters/iterators can run user code. Transfer entries need not be reachable from the input: successful transfer still detaches them, without adding them to the result. Move reachable transferred storage exactly once into the receiving graph; every sender alias/view must observe detachment, while receiving views share the transferred buffer with their original ranges. Invalid/detached/out-of-bounds views fail rather than silently truncating. No clone operation may introduce partial detachment on validation, serialization or detach failure; user code's own side effects cannot be undone. The old sequential detach loop can fail after an earlier detach, so its comments are not evidence of transactional ownership. Establish an explicit commit/enqueue failure policy so a failed send cannot silently lose detached storage or publish a partial message.
  - Errors: unsupported symbols, callables, globals, DOM/other uncloneable host objects, promises, weak collections, proxies and shared buffers must produce DataCloneError (name and legacy code 25), not shallow copies or generic TypeError. Distinguish those failures from API argument TypeError and exceptions thrown by user getters/iterators. Construct errors through current native error/DOMException facilities, never Boa's opaque-error helper.
  - Callers and verification: clone synchronously at `Web.MessagePort.postMessage` before enqueueing so subsequent sender mutation cannot affect the delivered data; reconstruct receiving values before the existing MessageEvent/callback path delivers them. Wire any requested global `structuredClone` through current native global registration/dispatch using the same semantics, not removed `runtime.rs` hooks. Keep string-only IPC's contract explicit; do not invent a Worker framework or claim worker integration where there is no caller. Before marking this follow-up complete, exercise the actual native MessageChannel/onmessage path for independent sender/receiver mutation, cycles/aliases, shared view buffers, successful transfer/detached sender access, duplicate/unsupported/detached transfers, throwing getters/iterators, getter-triggered detachment and multi-buffer failure ownership. Verify start/close/poll delivery behavior and no delivery on serialization failure. These are future acceptance requirements; this artifact-only review ran no compiler, tests or runtime.

- [ ] Native DOM API owner: restore TreeWalker traversal through the current `packages/blitz-script/src/native/dom.rs` document dispatch. NodeFilter constants exist, but current native sources expose neither `createTreeWalker` nor traversal methods. Required behavior: root/currentNode identity, root-bounded directional movement, node-type masks, callable and acceptNode-object filters, FILTER_SKIP descending into children, and FILTER_REJECT pruning a subtree. Historical implementation is available in commit `6a3e5bfe`; it used the removed Boa runtime and is a semantic reference, not an applicable patch. Verify these behaviors through the current native document before claiming compatibility.

- [ ] Native event API owner: complete KeyboardEvent initializer fields in `packages/blitz-script/src/native/events.rs`. Current constructors copy key/code and modifier fields but omit location, repeat and isComposing. Preserve supplied values and standard defaults, and verify constructed events retain their KeyboardEvent/Event identity and dispatch to native DOM listeners. The old YouTube compatibility patch used removed Boa constructors and ScriptDocument tests; do not restore those APIs.

- [ ] Native iframe owner: verify realm identity, stable `contentWindow` proxy, parent/top relationships and parent-aware HTML document construction through `ScriptDocumentBackend` and `NativeDocumentRuntime`. Current owners are `packages/blitz-script/src/native/dom.rs`, `native_document.rs`, `application_document.rs` and `packages/blitz-dom/src/iframe.rs`. Preserve inherited configuration and stale-generation rejection. The retired Boa frame-tree snapshot is not an implementation to restore; reproduce missing behavior against the native architecture before changing it.
